# 启动诊断

遇到“本地服务未就绪”等启动错误时，先运行诊断工具，再根据报告定位。工具适用于 Windows 标准包，已按 1.2.0 与 1.2.1 的目录布局设计，可重复运行；无需安装 Python、Node 或以管理员身份运行。

## 使用方法

1. 下载 `WechatVibe-diagnose.bat`，放到 `WechatVibe.exe` 所在目录。
2. 先复现一次启动错误并关闭错误弹窗，再双击诊断 BAT。启动失败弹窗会附上启动器输出的最后一行，完整内容追加在安装目录的 `logs/desktop-launch.log`（带时间戳）；诊断时可以直接把该文件末尾几行一起提供，不必只描述「本地服务未就绪」。
3. 等待结束，将同目录新生成的 `WechatVibe-startup-report-日期-编号.txt` 发给维护者。目录不可写时，会尝试保存到 Windows 临时目录，并在窗口中显示位置。

每次运行生成独立报告，不覆盖以前的结果。不必发送聊天截图、整个 `.local` 目录或原始日志。

## 检查范围

- Windows 版本、系统位数、客户端版本。
- 关键文件是否存在、大小，以及用于人工比对的文件 SHA-256；仅有哈希不代表文件已通过官方完整性验证。
- 安装、客户端及已有运行目录的写入能力；只创建并删除本次探针文件，不创建账号目录或修改现有文件权限。
- 内置 Python、Node 能否运行，以及常用本地依赖能否导入。只调用包内运行环境，不回退到系统 Python 或 Node。
- 本机回环连接能力、默认服务端口是否存在 TCP 监听。端口有监听不等于应用健康，不请求 `/api/health`。
- 最近两份启动日志末尾的异常摘要：已知异常类型、已知模块或代码文件名、行号及 Windows 错误码；附日志修改时间，作为历史线索。

不启动应用或 bridge，不调用模型，不访问微信数据库、账号配置或 API Key，不读取含控制令牌的进程记录，不上传任何内容。报告不复制完整日志、绝对安装路径、用户名、环境变量值或异常原文。环境变量仅记录是否设置。

### 启动身份校验

桌面端必须由本应用的 shell 拉起：launcher 检查 `WECHATVIBE_SHELL_PID` 是否出现在当前进程的祖先链上，最多上溯 4 层。源码运行加虚拟环境（venv 或 py launcher）会多一层解释器，因此不再要求 shell 是直接父进程；打包版自带 runtime，没有中间层，行为与之前一致。校验失败时日志里会看到 `Desktop startup identity is invalid`。这条校验只在桌面端注入 `WECHATVIBE_SHELL_PID` 时生效；`npm run start:service` 手动起服务不带该变量，不受影响。

## 验证边界

诊断报告用于区分文件、依赖、目录及启动环境问题，不会自动修复，也不代表应用已能正常启动。缺少某个可选依赖不一定是当前启动故障的原因，需要结合错误摘要判断。

工具跳过含目录重解析点的运行环境与日志路径，避免诊断扩散到其他目录。源码保存在 `scripts/diagnose-startup.bat`；向用户提供时，将其复制为 `WechatVibe-diagnose.bat`，无需附带其他脚本。后续运行环境或目录结构变化时，应同时更新此工具。
