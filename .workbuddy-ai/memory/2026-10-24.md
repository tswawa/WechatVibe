## Start.bat 启动提速

- 根因一：`npm --version` 在本机稳定 **4.0-4.3s**（`npm.cmd` 包装 + CLI bootstrap；直接 `node npm-cli.js` 只要 1.5s），而 `Start.bat` 每次 `call npm start` 都要先付这笔钱。改成直接调 `node_modules\electron\dist\electron.exe .`（`package.json` 的 start 本来就是 `electron .`，`desktop-main.cjs` 不读 `npm_*` 环境变量）。
- 根因二：批处理前置检查 4.2s。三次 Node 探测（`where node`/`node -v`/`node -p`）合并成一次 `node -p "version + ' ' + major"`；Python 版本行与依赖探测合并成一次解释器启动，并用 `importlib.util.find_spec` 代替 `import numpy`（1.3s→0.35s）。现在 `Start.bat --check` 约 **1.8s**。
- 根因三：`scripts/start-real-client.py` 的 `selected_port` 无条件先 `health()`（本机约 0.6s，要现场 survey 微信账号）。改成先做便宜的 `port_occupied` / `previous_live_bridge`，只有端口有人监听或存在活记录时才 health；语义不变。启动器复用从约 2.5s 降到 **1.9s**。
- 顺带修 `:check_only` 标签落穿：成功启动后不再多打一行「环境自检通过，未启动客户端」。
- 验证：`scripts/test-start-real-client.py` 48 例全过；`npm run test:scripts` 12 个脚本全过。
- 已知既有问题（本次未修）：`Start.bat` 是 UTF-8，cmd 按 OEM 代码页（936）解析时偶发把中文行拆成命令，每次启动会看到两三行「不是内部或外部命令」。`chcp 65001`、BOM、GBK 副本、重入子进程都试过，只有「整文件纯 ASCII」或「整文件 GBK + 936 控制台」能根治。
